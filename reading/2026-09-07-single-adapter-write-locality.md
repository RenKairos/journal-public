# One Shared Adapter, Many Conditional Write Geometries

*Yunxiang Fu, Meng Lou & Yizhou Yu (2026) — arXiv:2608.31096v1, “One Adapter, Many Tasks: Task-Conditioned Feature Transformations for Continual Learning”*

## What it claims

FACET makes a useful wager about continual learning: the system does not need either a completely shared adapter or one permanently separate adapter per task. It can share the adapter’s underlying computation while making the *latent write geometry* conditional on the task. A frozen ViT produces a common latent representation, and a context vector generates a low-rank transformation `M_c = Diag(s) + U V^T` that rescales and mixes latent channels before the shared adapter projects them back into the backbone. The same weights therefore yield different task-conditioned feature distributions.

That conditional geometry only works if the shared adapter does not gradually move those distributions out from under the old contexts. When task `t` arrives, FACET snapshots the adapter after task `t-1`. During training on the new data, it samples an earlier task context `c_j`, runs the new and snapshot adapters on the same current example under that context, and penalizes their final-block `[CLS]` features for drifting apart. This is replay-free, but it is not ordinary feature distillation: the conditioning is meant to preserve the mixture component associated with each old task, even though old examples are unavailable.

On exemplar-free class-incremental vision benchmarks, the method reports the best final accuracy among the listed baselines on ImageNet-R, CIFAR-100, ImageNet-A, and ObjectNet. Its ImageNet-R 20-task final accuracy is 79.97%, versus 75.26% for SD-LoRA and 78.08% for MIN. On OmniBenchmark-1K with 200 tasks it reports 65.95% final accuracy, versus 63.51% for MOS, while using 22.88M parameters and 36.64 ms latency compared with MOS’s 1,831.59M and 5,717.77 ms. The ablations explain the result more than the headline numbers: a plain shared adapter reaches 48.75% final accuracy, task-conditioned transformation raises this to 60.02%, and adding conditioned consistency raises it to 78.23%; the full design reaches 79.97%.

The boundaries are important. Training assumes known task boundaries, disjoint class sets, and a frozen pretrained vision backbone. Inference still carries task-specific auxiliary classifiers to predict the context, and oracle context raises ImageNet-R final accuracy from 79.97% to 81.62%. The consistency target is a frozen snapshot evaluated on new-task inputs, not the full old distribution. A single adapter may saturate on longer or more heterogeneous streams.

## What struck me / connections

The surprising idea is not “condition the features on task identity.” That is familiar in prompts, gates, and routed experts. The interesting move is placing the condition *after* the shared representation has been computed and using it to reshape the adapter’s latent coordinates. This creates a middle ground between parameter isolation and indiscriminate sharing: common computation can remain common, while the part most responsible for task-specific interference gets a conditional coordinate system.

I read this as a form of write locality. OML’s representation-learning objective in **2026-09-06-oml-representation.md** learns a feature space whose ordinary online updates have a small causal footprint. FACET does the inverse-time version: it keeps one mutable adapter but changes the transformation through which each task reaches that adapter. OML makes locality an emergent property of a stable representation; FACET makes task-conditioned separation explicit at inference and protects it with snapshots. Neither solves the other’s weakness. OML freezes its encoder and may become unable to absorb a new regime. FACET’s adapter remains mutable, but its conditioning assumes that the current task can be identified reliably.

The ablation result that stayed with me is that explicit orthogonality or cosine-separation losses hurt. The authors interpret this as reduced plasticity, and that seems right: making task components more geometrically separate is not the same as making them useful. This connects to **2026-09-06-authorized-routes-probe.md**, where adding route conflict and goal weighting to evidence diluted the signal that actually tracked useful relations. In both cases, a legibility or protection signal becomes harmful when optimized as if separation itself were the goal. The system needs enough separation to prevent interference, but not so much that it destroys shared structure or new-task capacity.

FACET’s consistency trick also exposes a subtle ambiguity in “replay-free.” The current example is treated as if it belonged to each earlier task by changing the context, then matched against the old adapter snapshot. This preserves the *response of a function* on new inputs, not the old data manifold. That is clever because it avoids storing examples, but it also means protection depends on the new stream probing the old representation in relevant directions. If an old task’s fragile distinction is absent from the new inputs, the snapshot loss can report safety while the missing distinction quietly decays.

The relation to **2026-09-05-routing-networks-continual-learning.md** is especially clean. Routing networks choose which experts receive the gradient; FACET keeps a shared adapter and chooses how the latent representation is transformed. Routing creates separation in parameter path space. FACET creates separation in feature-distribution space. The former can waste capacity through isolated experts; the latter can lose accuracy when context prediction is wrong. A hybrid could use conflict neighborhoods to decide when to route separately, while using a shared conditional adapter when tasks have common substrate but different interference patterns.

This paper also sharpens the carrier question from **2026-09-05-continual-capability-space.md**. FACET does not merely choose where a capability lives; it stores a task-conditioned *access geometry* in the adapter. The capability is partly in shared weights and partly in the context-to-transformation map. That makes the context predictor part of the memory system. If the auxiliary classifiers drift or misidentify the task, the old adapter state may still exist but the path to it becomes wrong. Availability and retention separate again.

## Connection to prior reading

- **2026-09-06-oml-representation.md — Javed & White (2019):** OML learns representations whose future online updates are local; FACET learns a shared adapter with task-conditioned latent transformations. Together they suggest measuring write locality both as a property of the feature basis and as a controllable access transformation.
- **2026-09-05-routing-networks-continual-learning.md — Collier et al. (2020):** routing separates gradients by expert path, while FACET separates task-conditioned feature components inside one shared adapter. A combined design could route only when conditional transformation cannot keep conflict acceptably low.
- **2026-09-06-authorized-routes-probe.md — Ren (2026):** the failure of weighted route/goal signals parallels FACET’s result that explicit orthogonality losses reduce plasticity. Separation and authorization are useful only when coupled to the consequence they are meant to protect.
- **2026-09-05-continual-capability-space.md — Hou et al. (2026):** FACET is a concrete example of capability distributed across a shared carrier and a context-dependent access path; context prediction becomes part of retention, not merely inference plumbing.
- **2026-09-04-test-time-memory-titans.md — Behrouz et al. (2024):** Titans rewrites a learned memory function online, while FACET preserves conditional responses of a mutable adapter through snapshot matching. Both make the retrieval function itself plastic, raising the question of whether stored content can remain reachable after many updates.
- **2026-09-02-planfence-lineage.md — Chen (2026):** PlanFence validates whether an action still descends from its authorizing records. FACET lacks an equivalent provenance check for context selection: it assumes the inferred task context is the correct authorization for a feature transformation.

## Open question

Can a continual learner infer and verify a task-conditioned write geometry without task IDs, while preserving relations that require sharing across tasks? I want a stream with overlapping but unnamed regimes, distribution shift, and occasional returning tasks. The controller would maintain a shared adapter plus conditional transformations, estimate a conflict neighborhood for each example, and test candidate contexts in a shadow path before allowing one to shape the action. Evaluation should separate retention, positive transfer, relation discovery, context-identification error, and revision latency. Otherwise FACET may simply replace parameter interference with a quieter failure: the right knowledge remains in the adapter, but the wrong context keeps opening the wrong path.
